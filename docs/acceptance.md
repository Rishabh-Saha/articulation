## Required production setup

Use the detailed steps in [README.md](../README.md). These account-level steps have not been performed by the agent:

1. Create/select a Firebase **Spark** project, enable Google sign-in only, and create Firestore in production mode.
2. Deploy the current `firestore.rules`, including the optional `reflection.notes` field. **An existing deployment must update its rules before deploying this app update.** Old entries and old v2 JSON backups remain readable; missing notes default to an empty string. Old rules will reject new saves without deleting the local draft.
3. Add the four **public** Firebase web-config values from `.env.example` locally and in the existing Cloudflare Worker build settings.
4. Deploy the app and backend to the existing **Cloudflare Worker on Free**, keep its hostname authorized in Firebase Auth, and verify production CSP, sign-in, saving, and cross-device restoration.
5. Record a real Day 1 entry; confirm “Saved to cloud”; verify another browser and a phone; export JSON and verify its contents. Keep the export somewhere private outside the browser.

Gemini automation is a separate, incomplete milestone. See [implementation and activation](automatic-analysis.md) for the disabled-by-default backend, bindings, and outstanding live tests. Do not add its secret to a `VITE_*` variable. The user explicitly requested share-link retrieval. Keep it limited to the selected public shared item, bounded in size, authenticated, and restricted to known Google hosts; never bypass sign-in or score a thumbnail. Keep the manual path working when free quota or AI access is unavailable. If sending a video to Gemini's free tier, show the provider-use privacy notice and get a deliberate opt-in first.

## Regression checks

- `npm test`: old backups, notes-only days, durable drafts, edits during save, read-only store writes, conflicts, and missing-cloud recovery.
- `npm run test:safety`: two tabs sharing browser storage, import blocked in a read-only tab, safe editor handoff, reload persistence, one shared note between Notebook and Reflection, search, backup coverage, and mobile layout.
- `npm run test:cloud`: isolated browsers, offline conflicts, notes sync, unexpected deletion in the demo emulator, truthful missing-copy status, and explicit restoration.
- `npm run test:rules`: account isolation, rating validation, full scored records with notes, stale revisions, and deletion prevention.
- `npm run test:e2e` and `npm run test:a11y`: the general workflow and automated accessibility checks.

For a modern browser on HTTPS (or localhost), Web Locks grants one journal tab permission to write. Other tabs cannot edit or import and refresh from storage events. When the writer closes, the waiting tab reloads the latest disk state before becoming the editor. Unsupported or insecure browser contexts pause editing rather than risk overwriting drafts. This coordinates one browser storage partition; Firestore transactions handle different devices.
